Field notes · march 14

Why I left the framework treadmill

I used to ship a new portfolio every year. Some years it was Gatsby, some years it was Eleventy, one year it was a custom Astro thing I'd built on a flight. The pattern was always the same: a month of rebuilding, a month of being proud of it, and ten months of dreading it.

The thing I never built, in any of those rebuilds, was writing. It turns out a fast site nobody publishes on is a slow blog.

What changed

I picked the most boring stack I could find — flat HTML, a Makefile, a server that doesn't restart — and I haven't touched the toolchain in 14 months. In that time I've published 27 posts.

  • One post a fortnight, instead of one rebuild a year
  • RSS works because I never broke it
  • Webmentions arrive without me thinking about them

The fastest way to make a slow blog is to spend a year picking a stack.

I still build new sites for clients on whatever the project requires. But for personal writing — for the place I want to come back to in five years — boring is the answer. Boring outlives novelty.

Code, when needed

For inline code: I run make publish and that's the entire deploy step. The Cmd + S save in my editor triggers it via a file watcher. Block code looks like this:

publish:
    rsync -avz --delete \
      build/ deploy@server:/var/www/site/

ElementDefault treatment

ul · li::beforeCustom marker bullet in UT Orange
ol · ::markerRoboto Slab, marker color

code · preJetBrains Mono on cream code-bg
kbdBoxed Mono with 1px ink border
table · theadSky-blue thead, ink rows, thick bottom rule
hr4px marker bar at 60% width, slight rotation

All of the above are styled in tokens.css at the element level, so a Markdown post compiles to the same rendering as the demo above without adding any classes.
